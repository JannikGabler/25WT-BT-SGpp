Status: BLOCKED · Date: 2026-11-14 · Base commit: cf698f31d
Recommendation: accept after applying the drafted `perf_reference.cpp` patch (protected) — memory −19 % geomean (27 MEM−; sg d2 L20 620 → 329 MiB, dsg b1 d20 218 → 83 MiB), generation 2–30× faster, e2e sum 1.007x; the only refcheck FAILs are `nodeChecksum` of the 106 shifted-domain cases, because `getNodesPerDim()` now returns domain nodes (agreed change (1)); with the patch refcheck = before (131 OK, known WARN).

## Change
- **Storage** (`SparseGridBase`, both grids): `LvlMIVec levels_` (moved in from the MI-set generation, owned: never aliases an `MIVecSGGenInstr`'s vector), `std::vector<CTCoeffType> coefficients_`, `NodeTable nodeTable_`, cached maxima, `OperatorDataCache` (moved up from the DSG). Was `std::vector<TensorGridCTData>` (3 heap blocks per TG).
- **`NodeTable`** (`grids/node_table.{hpp,cpp}`, new public): one node list per (dim, level 0…maxLvl(dim)), row = `firstRowOfDim[dim] + lvl`, counts = row length; already mapped with `tools::mapToDomain` (bitwise the evaluated points). SG rows: regular nodes; DSG rows: delta nodes (nested: each node once). Dimensions with equal `NodeGenFunc*`, `Lvl2GPCntFunc` and domain interval share rows. Each row is its own `DataVector`, allocated and generated by the thread that generates it (`tools::node_table_generation::genNodeTable`, replaces per-TG generation).
- **Views**: `TensorGridView` (levels + raw row pointers of the table: `nGPInDim`, `nodesInDim`, `getGPCntPerDim()`/`getNodesPerDim()` copies, `getGridPoint`, `toTensorGrid()`), `TensorGridCTDataView {mi, coefficient, tensorGrid}` (+ `toTensorGridCTData()`, `operator->` trick), random-access proxy iterator `misc::TensorGridCTDataIterator`. Grids: `getTensorGrid(i)`, iteration, `getTensorGrid(mi)`, `getLevels()`, `getCoefficients()`, `getNodeTable()`. Protected `perf_e2e.cpp` / `perf_reference.cpp` compile unchanged (proxy keeps `.mi/.coefficient/.tensorGrid.*`; `getNodesPerDim()` returns a concatenated copy, binds to `const DataVector&`).
- **Operators**: kernels take `TensorGridView`; SG quadrature / global interp read nodes from the table (no `mapNodesOntoDomain`, no per-thread `nodesPerDim`: −268 MiB zero fill at d2 L20); DSG kernel reads the table, copies only the row dimension's nodes into a growing scratch (`rowNodes`; reading the table directly made `micro/dsg/row_loop` b0 d7 20 % slower at equal instructions, IPC). SG global / linear interpolation keep their normalized-coordinate math on a lazily built `misc::UnitNodeTable` (operator data): computing in domain coordinates selected other corners for query points on nodes of shifted domains. Lin-interp bracket: branchless lower bound, view by const& (by value: 32-byte stack copy, +15 % at d2). `CTCoeffTrie(levels, coeffs)` / `ClosureTrie(levels)` read the contiguous levels; `comp1DWeights`, DSG indices take `maxLvl` from the table (no TG scan); `DSGLinInterpIndex` generates its unit delta nodes itself.
- Docs: Doxygen of all touched classes, CLAUDE.md §2, `module-reference.md`, `python-bindings.md`. Python: `getTensorGrid*` return owned copies (domain nodes); new `getLevels`, `getNodes(dim, lvl)`, `nNodes`, `maxLvl`.
- Files: new `grids/{node_table,tensor_grid_view}.{hpp,cpp}`, `miscellaneous/tensor_grid/tensor_grid_combination_technique_data_view.{hpp,cpp}`, `miscellaneous/iterators/tensor_grid_ct_data_iterator.hpp`, `miscellaneous/data_contexts/unit_node_table.hpp`, `tools/sparse_grid_generation/node_table_generation.{hpp,cpp}`; deleted `tools/sparse_grid_generation/sparse_grid_generation.{hpp,cpp}`, `tests/grids/sparse_grid_base_test.cpp`; 72 tracked files changed (grids, generation, all operator tools/scratches/contexts, tries, DSG indices, `constants.hpp`, `type_defs.hpp` (`LvlMIView`), umbrella header, `combigrid.i`, tests, `perf_micro.cpp`, `perf_interp_sol.hpp`, `perf_interp_explore.cpp`). Deleted / proposed-for-deletion list and design decisions: `results/WP-18/design-and-obsolete-code.md`.

## Attempts not kept
- Domain-coordinate SG interpolation (no unit table): corners differ for points on nodes of shifted domains (`dsg_linear_interpolation/Each_Distinct_Corner…` failed) → unit table.
- Flat node buffer: serial zero fill, 16-thread generation sg d2 L20 shifted 27 → 81 ms → per-row `DataVector`s (22 ms).
- View with `const NodeTable*`: 4 dependent loads per node list → raw row pointers. Views by value in the lin-interp kernel (+15 % at d2) → const&; by-value kept elsewhere (no difference).
- DSG kernel reading all nodes from the table (row_loop b0 d7 0.75, e2e dsg b0 −5 %); copying all projected dimensions = no better than the row dimension only.

## Profile shift / follow-ups
- WP-05: weights keyed by the table row (or (QuadRule*, n)) would remove the remaining per-thread `weights1D` zero fill (sg d2 L20 still 329 MiB, mostly 16 × 16.8 MiB).
- Remaining ~1–2 % on DSG b0 / interp-dsg and SG interplin d2 (per-call unit-table lookup + views): placement-sensitive, low priority.
- Delete dead code (ranked list in `design-and-obsolete-code.md`: node-lookup stub, extensive SG, `getQuadRulesForAllDims`, `TensorGrid::getNeighborsForLinInterpolation`).
- Adaptive CT: rows are independent `DataVector`s (adding levels appends rows), but views hold raw pointers into the row vector → growth needs reserved/stable storage and an incremental `setStorage`; DSG operator data needs invalidation (details in the design note).
