# Design and Implementation of the Sparse Grid Combination Technique in SG++

Bachelor thesis by Jannik Marcel Gabler, Scientific Computing group of Prof. Dr. Dirk Pflüger, University of Stuttgart (examiner: Prof. Dr. Dirk Pflüger; supervisors: Prof. Dr. Dirk Pflüger, Carmen Wabartha, M.Sc.).

This directory is a faithful Markdown conversion of the LaTeX thesis in `bachelor thesis/thesis/` (source of truth, read-only), produced as a knowledge source for future Claude Code sessions working on the SG++ combigrid module. It preserves every definition, derivation, equation, algorithm, table, and citation of the original — nothing was summarized or shortened — but drops typographic/publication concerns that do not matter to a machine reader.

## Abstract of the whole work

High-dimensional numerical problems suffer from the curse of dimensionality, which makes full-grid methods computationally infeasible; sparse grids mitigate this by drastically reducing the number of grid points while preserving good approximation properties, and the combination technique (CT) is a particularly practical sparse-grid approach because it builds sparse-grid solutions from independent tensor-grid subproblems. This thesis designs and implements a new CT module for the C++ sparse-grid framework SG++, replacing the previous SG++ combigrid implementation, whose architecture, documentation, and performance had become limiting. The design is informed by a comparative analysis of three other sparse-grid frameworks — Tasmanian, the Sparse Grids Matlab Kit (SGMK), and sparseSpACE — and results in a more composable architecture built around four concepts: source functions, sparse grid generation instructions (blueprints), sparse/tensor grid data structures, and mathematical operators (quadrature, global and linear interpolation). Its two central technical contributions are an on-demand tensor-grid assembly scheme that avoids the memory blow-up of fully materialized tensor grids, and a new "dimension-separated" algorithm for computing combination-technique coefficients for arbitrary downwards-closed multi-index sets in $\mathcal{O}(|I| \cdot d)$ time. The module is validated on three applications (quadrature of an oscillatory function, global-polynomial interpolation, and forward uncertainty quantification of an electron-beam attenuation model) and benchmarked against the three other frameworks, showing the best memory efficiency and CPU utilization of all four, and the best runtime in low dimensions, while Tasmanian and the SGMK overtake it at higher dimensions due to their reduced sparse-grid representations.

## What to read for which task

- **Understanding or re-deriving the mathematics of sparse grids / the combination technique** (definitions, the inclusion-exclusion principle, CT coefficients, asymptotic complexity): read [02-sparse-grids.md](02-sparse-grids.md) first; it is the mathematical foundation every later chapter assumes.
- **Understanding the public API of the new SG++ combigrid module** (what classes exist, how to call them, what a basic script looks like): read [04-new-ct-module-for-sgpp.md](04-new-ct-module-for-sgpp.md).
- **Understanding *why* the internals are built the way they are, or extending/optimizing the internal algorithms** (tensor-grid assembly strategy, node generation abstraction, quadrature/interpolation formulas, the CT-coefficient generation algorithms and their proofs, boundary handling): read [05-algorithmic-and-design-choices.md](05-algorithmic-and-design-choices.md) — this is the most implementation-relevant chapter for someone modifying the combigrid module's internals.
- **Writing new examples or tests, or understanding expected numerical behavior**: read [06-application.md](06-application.md) for three complete, runnable-style C++ examples with expected result tables.
- **Comparing design/performance trade-offs against other sparse-grid frameworks, or justifying a design decision**: read [03-existing-frameworks-and-motivation.md](03-existing-frameworks-and-motivation.md) (qualitative) and [07-comparison-between-frameworks.md](07-comparison-between-frameworks.md) (quantitative benchmarks).
- **Planning future work / checking whether a feature was already considered and why it's missing**: read [08-conclusion-and-outlook.md](08-conclusion-and-outlook.md).
- **Reproducing the benchmark or the four-framework example code**: read [09-appendix.md](09-appendix.md).
